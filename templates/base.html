{# Platform-wide player finder. Mid-auction someone says a name and nothing else in the app answers "where is he?" — the pool table lists only the undrafted, a rostered player needs the right one of eleven panels opened, a minor is in a second table inside that panel, and a bought-out player appears nowhere at all. It lives in the NAVBAR for three reasons, all checked: the navbar is outside #app, so a panel swap cannot destroy an open result list; it has no `overflow`, so the absolutely-positioned card is not clipped (the app's only `overflow` is `.auction-grid`'s, inside #app); and it already establishes a `z-50` sticky stacking context. Deliberately NOT a DaisyUI `.dropdown`. That component gates `.dropdown-content` on `:focus-within`, so mousedown on a result blurs the input, the card goes `visibility:hidden` before mouseup, and the click never lands. Visibility here is decided server-side instead — an empty response renders no card — which is also a fact `TestClient` can assert. `input` rather than `keyup`: keyup misses paste-from-menu and the native clear button on `type="search"`. `changed` plus the delay is what keeps arrow keys and modifiers from firing a request. No `hx-sync` — htmx already queues a second request from the same element as "last" (`htmx-1.9.10.min.js`, `queuedRequests`), so responses cannot arrive out of order, and adding one would abort the in-flight request instead. `focus` is the second trigger and it is NOT redundant with `changed`. Clicking away dismisses the list but leaves the query in the box, and `changed` compares against a value htmx cached at trigger time — so coming back and re-typing the same surname fires nothing and the box looks broken. Measured. A focus with an empty box costs one request that answers 200 with an empty body. The mount is unconditional and empty (`explanation.html`'s rule: a swap into a missing target is a dead swap), carries the only id in the whole feature, and positions the card without being it. #}

Keyboard shortcuts

Ctrl / ⌘ + Z Undo the last draft action — the same as the Undo button. Holding the keys does not unwind several picks.
/ Find a player — jumps to the header search, which says where anyone is: in the pool, on a roster, on a bench, in the minors, or bought out. Esc closes the results.
N Nomination recommendations — refreshes the nomination panel only, so it is safe to press mid-bid: the player, price and bidder toggles survive it.

Both are ignored while you are typing in a text box, a number box or a dropdown — so a name containing "n" types normally, and Ctrl+Z in a field undoes your typing rather than the last pick. Click a bidder logo and focus lands on a button, not a field, where N is live again.

Everything else is a click. Esc closes this.
