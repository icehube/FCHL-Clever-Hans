NO IDS ANYWHERE IN HERE, on any element. `main._dom_id` mints exactly one id per player and `team_panel.html` already owns it for the buyout dots; a second copy in this list would be a duplicate id that the roster scan then swaps twice. The mount (`#player-search-results` in base.html) carries the only id involved, and it is positioning alone — the visible card is this fragment, so an empty response renders nothing at all and the dropdown simply is not there. That is why there is no `hidden` to manage. THE WHOLE ROW is the click target, not a link inside it. A nested would be invalid markup, and on a pool row there is no team to link to anyway, so putting the navigation on the row is the only shape that behaves the same in all five states. `link_team` is guarded in `_search_rows` and is None unless the row should navigate, so this template never has to ask.
